# Constants

snapshotLockKey = a fixed integer key for the Postgres advisory lock that serializes snapshot writers.

completedDateSQL = select whether the updates table has a completed snapshots row with date_from and date_to equal to $1, or a completed snapshot_rebuild row whose range contains $1.
snapshotRowsExistSQL = select whether any snapshots row exists for date $1.
insertSnapshotSQL = insert a snapshots row (date, instrument_id, quantity, close_price, price_date) for one holding.
deleteSnapshotRangeSQL = delete the snapshots rows with date between $1 and $2.
priceDatesSQL = select the distinct prices dates between $1 and $2, ascending.
latestSessionDateSQL = select the maximum date from prices, null if none.
insertUpdateSQL = insert an updates row from every Update field.

# Functions

## Store.LatestSessionDate(ctx Context) (*domain.Date, error)

1. Select via latestSessionDateSQL.
2. Return the date, or nil when there is none.

#### Errors

- **1.** if the query fails, return the wrapped error.

## Store.RecordUpdate(ctx Context, update domain.Update) error

1. Validate update.
2. Execute insertUpdateSQL.
3. Return nil.

#### Errors

- **1.** if invalid, return the domain.ErrInvalidInput error.

---

- **2.** if the statement fails, return the wrapped error.

## Store.WriteSnapshot(ctx Context, date domain.Date) (domain.SnapshotResult, error)

1. if date is after today in Store.marketLocation, return ErrInvalidInput.
2. Open a transaction with withTx and take the advisory lock with snapshotLockKey for its duration.
3. Check completedDateSQL for date; if completed, return a skipped, complete result.
4. Value the date with valuedHoldings through the transaction.
5. Mark as an issue every holding whose price date is not date: "missing" without a price, "stale" with an older one.
6. if there are no issues, check snapshotRowsExistSQL, insert one row per holding via insertSnapshotSQL, and record a completed snapshots update with the row count.
7. otherwise log the date and each instrument's issue at warn level, and record an incomplete snapshots update whose error message names the symbols and their issues, writing no rows.
8. Return the result.

#### Errors

- **2.** if the transaction or lock fails, return the wrapped error.

---

- **3.** if the lookup fails, return the wrapped error.

---

- **4.** if valuing fails, return the wrapped error.

---

- **6.** if rows already exist, log the date at error level, return ErrSnapshotExists and write nothing.
- **6.1.** if an insert fails, return the wrapped error and roll back.

The update row and the snapshot rows commit together, so the marker never disagrees with the rows. An incomplete update is committed as well, the transaction ending without error. Reusing valuedHoldings keeps one definition of the valuation; the strict date test is what separates a snapshot from the tolerant live portfolio. A date with no active positions writes no rows and is recorded complete.
Quantities and prices pass through as decimal text; the market value column is generated by the database.

## Store.RebuildSnapshots(ctx Context, from domain.Date, to domain.Date, reason string) (domain.RebuildResult, error)

1. Validate: reason non-empty after trimming, from not after to, to not after today in Store.marketLocation.
2. Open a transaction with withTx and take the advisory lock with snapshotLockKey.
3. Delete the range via deleteSnapshotRangeSQL.
4. Select the price dates in the range via priceDatesSQL.
5. For each date in order, value it as in WriteSnapshot steps 4 and 5; if no issues, insert its rows.
6. if any date has issues, abort with an IncompleteSnapshotError for the first such date.
7. Record a completed snapshot_rebuild update with the range, reason and row count, then commit.
8. Log the completed rebuild at info level with the range, reason, dates and rows, then return the result.

#### Errors

- **1.** if invalid, return the domain.ErrInvalidInput error.

---

- **2.** if the transaction or lock fails, return the wrapped error.

---

- **3.** if the delete fails, return the wrapped error.

---

- **5.** if valuing or an insert fails, return the wrapped error and roll back.

---

- **6.** roll back so the deleted rows return, log the date and issues at error level, then record a failed snapshot_rebuild update with the range, reason and the error message in a separate statement, and return the IncompleteSnapshotError.

Dates come from the price table, not from a calendar, matching the rule that a snapshot exists only when price data exists. The range may be the whole history, so the transaction can be long; accepted for a personal portfolio. Concurrent daily writes wait on the advisory lock.
