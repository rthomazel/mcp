# investments-mcp

Personal investment monitoring MCP server: instrument registry, transaction ledger, positions and securities valuation, backed by its own PostgreSQL database. Go. Released as v0.1.0, image `ghcr.io/rthomazel/mcp/investments`, published from `investments/vX.Y.Z` tags.

Specification and plan: [`spc/`](./spc/spec.md). Models sit next to the code they describe. The server exposes MCP tools for instruments (`add_instrument`, `list_instruments`), the ledger (`add_transaction`, `list_transactions`), cash (`add_cash_transaction`, `list_cash_transactions`, `get_cash`), valuation and P&L (`get_positions`, `get_portfolio`), prices (`get_prices`, `refresh_prices`), history (`get_snapshots`, `get_value_history`, `rebuild_snapshots`) health (`get_status`, `list_updates`) and the notification outbox (`remove_event`). The price refresh runs at the times in `INVESTMENTS_MCP_PRICE_REFRESH_RUN_TIMES` (06:00 and 20:30 by default) and every monitor once a day at `INVESTMENTS_MCP_MONITORS_RUN_TIME` (07:00), in the market timezone. Notifications are driven by a YAML file named by `INVESTMENTS_MCP_NOTIFICATIONS_CONFIG_FILE`; see [`spc/notifications/spec.md`](./spc/notifications/spec.md). Which monitors run, and their settings, are in a second YAML file named by `INVESTMENTS_MCP_MONITORS_CONFIG_FILE`; a monitor with no entry does not run, see [`spc/monitors/configuration.spec.md`](./spc/monitors/configuration.spec.md). The portfolio extremes monitors announce each multiple of a configured percentage the securities value falls below its all-time high and each new all-time high, see [`spc/monitors/portfolio-extremes.spec.md`](./spc/monitors/portfolio-extremes.spec.md). The portfolio movement monitor announces a move of the securities value over a window that prices alone explain, apart from trades, see [`spc/monitors/portfolio-movement.spec.md`](./spc/monitors/portfolio-movement.spec.md). The allocation drift monitor announces each time a configured group of instruments leaves its allocation band, see [`spc/monitors/allocation-drift.spec.md`](./spc/monitors/allocation-drift.spec.md), and the price volatility monitor announces a price move that is a configured number of standard deviations of an instrument's usual moves, see [`spc/monitors/price-volatility.spec.md`](./spc/monitors/price-volatility.spec.md). The price target monitor announces a daily price range that reaches a configured price, see [`spc/monitors/price-target.spec.md`](./spc/monitors/price-target.spec.md), and the instrument drawdown and instrument all-time high monitors do for instruments what the portfolio extremes monitors do for the securities value, see [`spc/monitors/instrument-extremes.spec.md`](./spc/monitors/instrument-extremes.spec.md). Their descriptions, parameters and errors are in the models under `internal/handlers`.

## Develop

```bash
investments/run dev     # reads .env, see .env.example
investments/run mocks   # generate mocks before test
investments/run test    # set INVESTMENTS_MCP_TEST_DSN to include the database tests
```

`INVESTMENTS_MCP_TEST_DSN` is an admin DSN, for example `postgres://user:pass@localhost:5432/postgres`. Each test creates and drops its own database, so the role needs `CREATEDB`.
